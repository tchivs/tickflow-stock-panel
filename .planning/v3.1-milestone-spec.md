# v3.1 Milestone: 可信工作台与运维闭环 (Trusted Workbench & Ops Loop)

## 结论

下一里程碑应以打磨现有功能为主，做 v3.1「可信工作台与运维闭环」，暂不扩展新的大型量化能力。

### 判断依据

- v3.0 已通过 26/26 需求、6/6 集成链路，基础能力已经足够丰富，继续加因子、Agent 或市场只会扩大维护面。
- docs/aaa 的核心结论也是：数据契约 → 工具审计 → 可回放研究 → 工作台产品化，而不是继续堆 Agent。
- 当前缺口主要在"用户能否看懂、验证、操作"：
  - 首页已有市场、同步任务和监控，但缺少统一的数据源健康、待审批事项、最近报告与运行产物。
  - 数据质量 Banner 主要局限在 Alpha 工作台。
  - 生命周期、论点、因子晋升、纸面调仓的待确认事项分散在不同页面。
  - 监控已有规则、历史和冷却，但缺少文档要求的 test-fire、预算状态和通知链路诊断。
  - 尚未形成统一的工具调用审计页面。
- 规划资料自身也需要收口：STATE.md 一边写 v3.0 完成，一边写 Phase 50 未开始；PROJECT.md 仍显示"正在建设 v3.0"。

## v3.1 范围

### Phase 51：发布基线收口

- 统一 STATE/PROJECT/ROADMAP/REQUIREMENTS 状态。
- 执行并纳入 Vitest；补真实 LLM、Provider 降级、SSE 重连部署冒烟。
- 处理或明确关闭 Tier-2 stress matrix、成本近似等 v3.0 技债。

### Phase 52：全局可信度与工具审计

- 为 Provider、AI、通知、外部工具统一 ToolCallEnvelope：
  `tool、params、version、scope、response_shape、raw_hash、duration、error`。
- 建立统一 Provider Doctor 和数据质量 API。
- 审计内容脱敏，前端展示来源、日期、缓存、降级、schema 和失败原因。

### Phase 53：今日工作台与统一待办

首页集中展示：

- 数据新鲜度和 Provider 健康；
- 运行中/失败任务；
- 最近报告与研究产物；
- 监控触发；
- 生命周期、论点、因子晋升、纸面调仓的统一"待确认"收件箱；
- 每项都有明确下一步入口。

这正对应文档要求的"今天什么状态、什么信号、什么任务、什么风险、下一步点哪里"。

### Phase 54：监控与报告闭环

- 监控增加 synthetic test-fire、预算、冷却剩余时间、渠道健康和 digest 预览。
- 报告统一增加数据质量 Banner、证据卡、引用回链、多空冲突和失败路径。
- 运行页统一 Timeline、参数、工具调用、产物、失败重试与 SSE 恢复。

## 里程碑验收主链路

```
Provider 降级
→ 首页显示质量告警
→ 启动研究任务
→ SSE 查看运行过程
→ 查看工具调用和 raw hash
→ 报告回链证据
→ 产生待确认事项
→ 人工审批
→ 创建监控并 test-fire
→ 查看通知投递结果
```

## 暂不建议

- 多市场全面扩张；
- 新一轮因子/RL 搜索；
- 完整 Moderator 多 Agent 会议室；
- 大规模实时架构；
- 实盘交易。

完成 v3.1 后，下一功能型里程碑再考虑 v3.2「Moderator 研究会议室」。当前投入比例建议为：70% 产品闭环和可靠性，20% 测试与部署验证，10% 小型体验增强。
