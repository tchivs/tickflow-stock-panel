# Domain Pitfalls

**Project:** AthenaQuant v3.0 — replayable Alpha Factory + two-stage FactorResearchAgent  
**Domain:** Automated A-share factor discovery, governed evaluation, and research-only LLM orchestration  
**Researched:** 2026-08-08  
**Confidence:** HIGH for current AthenaQuant controls and local analyses; MEDIUM for the external validation/security references cited below

## Scope and decision rule

The failure modes below assume that v3.0 remains a research system: the model may propose a bounded hypothesis, while deterministic code owns parsing, candidate generation, evaluation, gates, persistence, and promotion. The final product must preserve the existing restricted Factor DSL, immutable revisions, one `FactorSignalChain`, measured-calendar walk-forward geometry, reserved exactly-once OOS, SQLite operational state, and zero automatic broker authority.

The local analyses are pattern evidence, not code to copy. AlphaMaster's constrained vocabulary/StackVM and formula-length mask are useful design patterns; its REINFORCE/RL training loop, elite replay, and untracked artifact gaps are not a statistical guarantee. PA_Agent's two-stage record, fail-closed preflight, partial-failure evidence, and approval-time evidence refresh are useful patterns; its source is AGPL-3.0-or-later and must not enter the MIT backend.

## Critical pitfalls in detail

### 1. Selection bias is multiplicative, not just `n_trials`

`backend/app/backtest/optimizer.py:26-27` already caps ordinary parameter grids at `GRID_MAX_COMBINATIONS = 2000`. `WalkForwardOptimizer.optimize()` explicitly records `n_trials`, `search_space`, `score_distribution`, and `oos_excluded`, and `backend/app/backtest/walkforward.py:204-215` defaults exploration away from the reserved OOS. The Phase 13 migration makes this durable: `wf_search_runs.oos_excluded` is checked, `wf_folds` is append-only with a uniqueness key, and `wf_validated_strategies.oos_evidence_fold_id` is unique (`backend/app/operational/migrations.py:1705-1794`).

Those controls do not automatically cover v3.0. Formula candidates, invalid parses, discarded candidates, mutation retries, prompt retries, alternate provider answers, and “try one more threshold” calls are all selection attempts. If only successful candidates are counted, the apparent discovery rate is overstated. If Stage 1 or Stage 2 sees final OOS-derived diagnostics, the Agent can contaminate OOS without directly calling an OOS evaluator.

**Required invariant:** the run manifest must distinguish `search_evidence`, `validation_evidence`, and `final_oos_evidence`; final OOS is inaccessible to candidate generation and Agent context. The deterministic winner is selected before the one-time OOS call. A failed OOS evaluation may be recorded as failed without permanently consuming the slot only under the existing Phase 13 rule; a successful OOS evidence row consumes it exactly once.

The external walk-forward source is consistent with this posture: its stated information-set discipline, repeated rolling tests, realistic costs, and honest reporting of non-significant results are a methodology reference, not proof that any particular candidate is profitable (MEDIUM confidence; [arXiv:2512.12924](https://arxiv.org/html/2512.12924v1)).

### 2. One signal chain must remain the semantic authority

`FactorSignalChain.compute()` (`backend/app/research/signal_chain.py:92-184`) binds a stored revision, resolves PIT membership, loads one governed panel, compiles the parsed expression, computes forward returns, applies finite/warm-up treatment, and generates per-date rank/z-score values. `FactorEvaluationService` explicitly delegates to that chain (`backend/app/research/evaluation.py:155-203`). A factory implementation that evaluates a Polars expression directly, a second AST interpreter, or an Agent-generated Python snippet would create a second semantic implementation.

The strongest reusable AlphaMaster pattern is the same one: immutable expression/vocabulary identity, restricted execution, and one feature/VM/signal path for backtest and serving (`../docs/aaa/alphamaster/DEEP-ANALYSIS.md:198-216`). The unsuitable pattern is importing its StackVM/RL code or assuming its serving JSON has complete provenance; the local analysis notes missing raw data hashes, registry snapshots, seed, commit, and report hash (`...DEEP-ANALYSIS.md:164-179`).

### 3. Versioning must cover semantics, not only syntax

The current DSL is already disciplined: `DSL_VERSION = "factor-dsl-v2"`, explicit `ALLOWED_FIELDS`/`DENIED_FIELDS`, `_FUNCTION_ARITY`, `_FUNCTION_PARTITION`, finite literals, bounded rolling windows, canonical serialization, and `shifted_label_ic()` (`backend/app/research/factor_dsl.py:17-69,311-377,392-519,580-606`). `FactorSignalChain._binding()` rejects an unsupported stored DSL version and mismatched dependency fields (`backend/app/research/signal_chain.py:213-222`). `FactorRegistry` persists canonical expression, AST and shape signatures, fields, operators, functions, DSL version, and provenance (`backend/app/research/factor_registry.py:126-168`).

A factory adds grammar/vocabulary state that is not yet represented by those fields. Any numeric token or operator ID must be derived from a stable ordered vocabulary and hashed, as AlphaMaster does (`../docs/aaa/alphamaster/DEEP-ANALYSIS.md:71-86`). Never “fix” a mismatch by reordering the new vocabulary or mapping an old token to a new operator. Store a new candidate/revision and force re-evaluation.

### 4. Determinism includes scheduling and tie-breaking

The existing optimizer accepts `max_workers=4` (`backend/app/backtest/optimizer.py:327-339`), so v3.0 must not assume a seed alone makes parallel search reproducible. The implementation should collect immutable per-candidate results and sort by a total key such as `(objective direction, canonical expression, candidate_id)` before selecting elites or winners. A candidate's seed must be derived independently of completion order. Polars reductions, score aggregation, and artifact serialization need stable ordering too.

AlphaMaster's analysis explicitly warns that elite replay, reward weights, restart count, and other search heuristics encode researcher preference and require recording configuration, seed, data version, and candidate distribution (`../docs/aaa/alphamaster/DEEP-ANALYSIS.md:133-145`). That is evidence for accounting, not a reason to add RL to this milestone.

### 5. Evidence must be durable and honest under interruption

The existing `PersistentAdvancedGraph` opens an SQLite checkpoint for each invocation, binds server-owned threads to job IDs, projects untrusted provider drafts through `_safe_draft()`, and records outcomes through `record_once()` (`backend/app/advanced/workflow.py:1-5,57-94,97-122,125-188`). PA_Agent's local analysis similarly recommends stage-by-stage cancellation checks and retaining partial records on timeout/schema failure (`../docs/aaa/pa-agent/DEEP-ANALYSIS.md:6-23`). These are the right patterns for FactorResearchAgent.

By contrast, the current walk-forward SSE helper describes a module-level `_wf_jobs` dictionary with a five-minute TTL (`backend/app/api/walkforward_sse.py:3-6,47-64`), and the backtest stream uses a module-level job and cooperative event (`backend/app/api/backtest.py:267-278,515-564`). Those can support a UI stream but must not become the authoritative Alpha Factory run ledger. A restart, duplicate POST, or late worker callback can otherwise create contradictory candidate and terminal records.

## Reusable patterns vs unsuitable or adversarial ideas

| Pattern or idea | Decision | Reason |
|---|---|---|
| Restricted AST/grammar, deterministic vocabulary fingerprint, bounded formula length | **Reuse** | AlphaMaster demonstrates why invalid programs and vocabulary mismatches should be rejected before expensive evaluation (`../docs/aaa/alphamaster/DEEP-ANALYSIS.md:71-98,108-129`). Implement independently in the existing Factor DSL. |
| One immutable signal implementation for evaluation, walk-forward, composite, and serving | **Reuse / hard requirement** | Already embodied by `FactorSignalChain`; prevents train–serve skew and preserves FACT-06. |
| Measured calendar, gap, PIT membership, search-fold OOS exclusion, exactly-once final OOS | **Reuse / extend to candidates** | Existing Phase 13 contracts and migration constraints are stronger than a new Agent-specific design (`backend/app/backtest/walkforward.py:82-111,204-215,245-271`; `backend/app/operational/migrations.py:1705-1794`). |
| Preflight → structured stage 1 → deterministic search/gates → structured stage 2 → durable record | **Reuse** | PA_Agent's staged record and fail-closed preflight are useful orchestration patterns (`../docs/aaa/pa-agent/DEEP-ANALYSIS.md:6-35`). |
| Agent-provided metrics, confidence, gate status, tool calls, or order instructions | **Reject** | These are untrusted claims and authority escalation. Recompute metrics and allow only bounded research annotations. |
| REINFORCE/RL, GPU-dependent search, unrestricted Python, arbitrary code generation | **Reject for v3.0** | Increases dependency, nondeterminism, candidate accounting, and execution-surface risk without satisfying the milestone's deterministic seeded-search decision. |
| Copying PA_Agent or AlphaMaster implementation/source | **Reject** | Local analysis identifies PA_Agent as AGPL-3.0-or-later (`../docs/aaa/pa-agent/DEEP-ANALYSIS.md:82-90`); current backend declares MIT. Reimplement patterns and maintain attribution/license review. |
| In-memory job/SSE state as authoritative run history | **Reject** | Useful for live projection only; durable SQLite event/candidate/outcome facts are required for restart, replay, and audit. |

## Phase-specific warnings

| Phase topic | Likely pitfall | Mitigation |
|---|---|---|
| Grammar/vocabulary | New operator added to arity table but not partition table, or old token IDs are silently reinterpreted | Compile-time/table consistency assertion, versioned vocabulary hash, rejected compatibility test. |
| Candidate evaluation | Search uses a full-lake universe or current membership instead of each fold's PIT membership | Require resolver and record membership fingerprint per fold; fail closed when the resolver is absent for governed runs. |
| Agent preflight | Model receives data that was not frozen or receives final OOS scores in context | Build prompt only from server-owned snapshot references; make final OOS inaccessible until deterministic selection is complete. |
| Provider fallback | Timeout/403/empty/invalid JSON collapses into a successful empty candidate | Typed terminal reasons and per-stage partial records; no silent fallback to stale output. |
| Promotion | A UI approval is treated as a durable authorization independent of evidence | Ticket digest and approval-time refresh; atomic consume with conflict on changed candidate/data/policy. |
| Deployment/release | A research-only endpoint imports a broker adapter “for later” or a dependency carries incompatible license terms | Import/call denylist, release SBOM/license check, runtime mocks, and research-only registration assertion. |
