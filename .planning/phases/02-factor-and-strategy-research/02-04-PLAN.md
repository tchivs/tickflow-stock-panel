<objective>
Expose one safe researcher workflow through the existing FastAPI host: factor validation/storage/discovery, natural-language draft/review/backtest/explicit retention, and completed-experiment comparison.

Purpose: compose the Wave 1/2 domain contracts without leaking provider authority, bypassing backtest guards, or creating a parallel HTTP application.
</objective>

<contracts>
- All factor save/evaluate routes parse and validate before writing or executing. Backtest range/symbol/concurrency safeguards from the existing backtest API remain in force.
- A natural-language result is a non-factor-persistent draft; it is returned with explanation and provider/model/version provenance, revalidated during an explicit reviewed-draft-to-revision transition, and cannot save itself or invoke execution.
- A natural-language factor becomes comparison-eligible only after that explicit human review creates a provenance-bound immutable revision, its successful validated backtest, and explicit retention of its immutable evidence snapshot.
- The API returns structured validation errors and never silently substitutes an expression or a default that disappears from retained configuration.
</contracts>

<task type="implementation">
  <name>Register typed research routes in the existing FastAPI application</name>
  <files>backend/app/api/research.py, backend/app/api/backtest.py, backend/app/main.py</files>
  <action>
Create an `APIRouter` under the existing host (for example `/api/research`) and register it in `app.main`; do not make another FastAPI app or router shell. Add Pydantic request/response models and route families for DSL options/validation; manual factor create/list/revision/history/similarity; hypothesis draft; an explicit reviewed-draft transition; validated factor-revision evaluation; experiment history/detail; explicit retain action; comparison candidates; and explicit side-by-side comparison.

For the reviewed-draft transition, accept the returned draft expression, explanation, provenance, and an explicit `reviewed=true` confirmation; reparse/revalidate it server side, verify its canonical expression is the reviewed draft, and create a new factor revision whose provenance embeds the provider/model/template metadata. Only this endpoint can turn a natural-language draft into a factor revision. Evaluation accepts that issued revision ID, never a client-declared natural-language flag; direct manual-factor routes must not let an unreviewed draft impersonate a reviewed revision.

Use `request.app.state` services created by earlier plans. Validate request shape and all run inputs before calling an evaluator. Reuse/refactor the existing backtest guard helper rather than duplicating server-range/symbol protections. When a factor run completes, create an immutable run/evidence record with `retained_at = NULL`; only an explicit retain endpoint can mark a completed validated record as comparison-eligible. Never accept a draft or failed/cancelled/unvalidated run for retention/comparison.

Amend the existing `/api/backtest/strategy/run` and its SSE completion path as the sole trusted strategy-experiment handoff: allocate and return a server-issued research execution handle before/with the registered strategy run, record `running`, atomically record a completed snapshot (including registered strategy identity/version, resolved config, metrics, curves/trades artifacts, governed manifest, and artifact checksums) only from the server-side `StrategyBacktestResult`, and record cancelled/failed diagnostics. The research retain endpoint accepts only this catalog-issued completed handle; it must reject client-supplied metrics/results, unknown/stale handles, and cancelled/failed handles. Preserve existing SSE result/reconnect/cancellation semantics and server concurrency/range guards.

Map domain `ValueError`-style validation failures to 400s, unknown resources to 404s, and availability/state conflicts to deliberate structured errors. Keep route handlers thin: parser, registry, evaluator, catalog, and hypothesis service retain domain ownership.
  </action>
  <verify>Run `pytest backend/tests/research/test_research_api.py backend/tests/research/test_hypothesis_workflow.py -q`.</verify>

    - A natural-language draft can only become a provenance-bound factor revision through the reviewed-draft endpoint, then be evaluated and explicitly retained; manual routes cannot bypass that transition.
    - An existing registered strategy creates a server-issued completed experiment handle from the existing backtest completion boundary; fabricated, stale, cancelled, and failed handles cannot be retained.
    - Comparison returns selected snapshots/deltas/warnings and no aggregate winner, while incomplete/unretained records cannot enter its candidate set.
