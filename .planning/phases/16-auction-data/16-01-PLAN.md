<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| data provider -> kline_minute parquet | Untrusted external minute bars cross into the governed lake here; timestamp integrity and session attribution must be enforced at this boundary. |
| preferences -> pipeline gate | A misconfiguration (or stale capability set) could make the pipeline silently skip or over-broaden minute sync. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-01 | Spoofing | `_minute_ts` / `_bucket_minutes` (free_stockdb_provider) | high | mitigate | Lock the 09:30 start-of-day anchor and the morning-session boundary with unit tests (`test_minute_timestamp_convention.py`); a pre-09:30 bar can never enter a morning bucket or a session/auction label. This is the data-integrity foundation of DATA-03's honesty guarantee. |
| T-16-02 | Tampering | `sync_and_persist_minute` write path | high | mitigate | The tracer (`test_minute_sync_verify.py`) snapshots daily-K partition sets + per-file sha256 before/after and asserts byte-identical lakes; the canonical-column and `Datetime("us")` assertions guard schema drift. |
| T-16-03 | Denial of Service | `_resolve_minute_symbols` (full CN universe) | medium | mitigate | Add the `minute_sync_symbols` scope knob (research pitfall 3) so operators can bound the sync set; `resolve_limit`/`rpm` batching in `sync_minute_batch` already rate-limits. |
| T-16-04 | Spoofing | capability gate (`can_sync_minute` / `Cap.KLINE_MINUTE_BATCH`) | medium | mitigate | The pipeline skips `sync_minute` (append to `skipped`) when the provider lacks the minute dataset or the user disabled it — asserted by the tracer's second test function. A stale capability can only skip, never fabricate data. |
</threat_model>
