<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| data provider -> auction probe service | Untrusted 集合竞价 claim (or a 09:30 bar dressed as auction data) crosses here; the probe must classify by timestamp window, never by provider labels. |
| auction_probe service -> /api/data/auction-probe -> frontend | The verdict is server-authoritative; the frontend must never synthesize or downgrade it. |
| indicators pipeline -> enriched parquet -> strategy filters | A mis-computed `open_gap` (cross-day lookahead) leaks biased factors into Phase 17 strategies. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-01 | Spoofing | `resolve_auction_probe` window classification | critical | mitigate | `available` is reachable ONLY from rows whose `datetime` is inside `[09:15:00, 09:25:59]`; all-`>= 09:30` or empty input yields `fail_closed`. Regression-locked in `test_auction_probe.py`. A provider's label can never grant availability — only observed timestamps can. |
| T-16-02 | Tampering | `/api/data/auction-probe` verdict + AuctionProbeCard | high | mitigate | Verdict is computed server-side (`resolve_auction_probe`) and the frontend maps only server `status` values; UI-SPEC "no client-side synthesis" enforced by the total state mapping in `AuctionProbeCard.tsx` and asserted by the honest-label regression tests. |
| T-16-03 | Tampering | `open_gap` computation (`compute_indicators` Pass 4) | high | mitigate | Factor contract is `open / prev_close - 1` using Pass-1 `prev_close` (`close.shift(1).over("symbol")`); the lookahead-guard fixture test (mutate day2 open, assert day1 unchanged) blocks cross-day leakage into Phase 17 strategies. |
| T-16-04 | Spoofing | `ProviderCapabilities.auction` / custom `auction` dataset config | low | accept | A user-configured custom source is operator-controlled by design (same SSRF surface as the existing daily/minute/realtime datasets); the probe treats declared capability as a probe *candidate*, never as proof — classification still requires in-window rows. No new network authority beyond the existing custom-source model. |
| T-16-05 | Information Disclosure | `/api/data/auction-probe` response | low | mitigate | The verdict carries only `source` name, `probed_at`, and a fixed `detail`; credentials are never included. `error` detail truncates the exception message to a bounded string. |
</threat_model>
