## 1. System Classification

**System Type:** Hybrid

**Description:** Controlled, stateful research automation for a single-user quantitative platform. LangGraph orchestrates bounded workflow steps while deterministic services own authorization, promotion, auditing, and sandbox enforcement. Good behavior produces traceable research artifacts and never turns a model suggestion into autonomous market action.

**Critical Failure Modes:**
1. An unauthorized, revoked, out-of-allowlist, or rate-limited agent job starts work.
2. A strategy, viewpoint, or experiment record loses immutable lineage, gate evidence, or audit attribution.
3. Untrusted strategy content escapes declared AST, import, timeout, or memory constraints.
4. An agent/model result changes a promotion, official stance, or execution state without deterministic validation and explicit human approval.

## 1b. Domain Context

**Industry Vertical:** 中国境内 A 股量化投资研究与个人决策支持

**User Population:** 在自托管单用户平台上工作的 A 股个人投资者、量化研究员，以及负责授权、数据与运行边界的运营者。

**Stakes Level:** High

**Output Consequence:** 归因观点、置信度表现、实验反馈和策略晋级结果会影响研究优先级与投资决策；本期不提交券商订单、不自动启用策略，任何晋级仍须人工批准。

**不良（领域专家会标记）：** 只报告总体胜率或平均收益，隐去样本量、覆盖期与基准；高置信度组并不优于低置信度组仍宣称置信度可靠。  
**风险级别：** High  
**来源：** 预测校准与投资业绩归因实务；阶段决定 D-03 至 D-05。

**维度：实验能否复算并检验原假设**

**不良（领域专家会标记）：** 看到回测结果后才改写成功标准，无法确定所用数据版本或参数，或把超时、验证失败和资源中止描述成策略被证伪或有效。  
**风险级别：** Critical  
**来源：** 可复现量化研究惯例；阶段决定 D-06 至 D-09。

**维度：策略晋级的样本外与稳健性证据**

**不良（领域专家会标记）：** 仅按单一夏普率或累计收益排名即晋级；在同一历史样本反复搜索后挑选最优结果；遗漏滑点、佣金、印花税、停复牌、涨跌停和流动性等 A 股可实现性约束。  
**风险级别：** Critical

**维度：受限研究自动化是否守住授权和代码边界**

**风险级别：** Critical

### Known Failure Modes in This Domain

- **事后偏差与数据泄漏：** 将复权修订、财报发布日期之后才可见的数据、指数成分股存活名单或模型训练截止日之后的事件混入历史窗口，会把不可交易的事后知识伪装成预测能力。
- **重复试验后的虚假发现：** 对同一 A 股历史样本反复变异因子、参数或提示词并挑选最佳结果，会提高偶然显著性的概率；未经独立样本外、滚动窗口和成本压力检验的候选策略不应晋级。
- **A 股交易可实现性失真：** 忽略涨跌停、停复牌、ST 风险、流动性、冲击成本、佣金和印花税，或使用不可在信号时点成交的收盘价，会令回测收益无法实现。
- **来源观点与置信度失真：** 转载、修订或不同证券覆盖范围的观点被错误归因或合并，会使“立场变化”和置信度分桶的业绩统计失真；缺失行情/基准被静默排除会进一步抬高命中率。
- **研究自动化越权：** 排队任务在授权被撤销、范围变更后仍执行，或自定义代码逃逸资源/导入限制，会破坏研究边界、审计可信度和本期“仅决策支持”的承诺。

**Selected Framework:** LangGraph

**Version:** 1.2.9

**Rationale:** Phase 4 needs durable, auditable, stateful workflows with explicit human gates and resumption. LangGraph continues the Phase 3 SQLite checkpointing implementation, remains compatible with the existing direct OpenAI-compatible adapter, and does not require an external queue or database. ## 3. Framework Quick Reference

LangGraph is the workflow and durable-resumption layer only. Its state is an execution record, not an authority record: authorization, allowlists, promotion decisions, sandbox admission, operational writes, and audit events remain in deterministic application services.

### Entry Point Pattern
```python
from pathlib import Path
from typing import Literal
from typing_extensions import TypedDict

from langgraph.checkpoint.sqlite.aio import AsyncSqliteSaver
from langgraph.graph import END, START, StateGraph
from langgraph.types import Command, interrupt


class AdvancedWorkflowState(TypedDict):
    job_id: str
    subject_ref: str
    authorization_id: str
    frozen_evidence_refs: list[str]
    suggestion: dict[str, object] | None
    gate_status: Literal["passed", "rejected"] | None
    human_decision: Literal["approved", "rejected"] | None


async def authorize_and_freeze(state: AdvancedWorkflowState) -> dict[str, object]:
    # Application service revalidates the short-lived token and current allowlist.
    # It derives scope and freezes evidence; it must reject before any model call.
    return await authorization_service.prepare_job(
        job_id=state["job_id"],
        authorization_id=state["authorization_id"],
        subject_ref=state["subject_ref"],
    )


async def generate_suggestion(state: AdvancedWorkflowState) -> dict[str, object]:
    # The direct OpenAI-compatible adapter receives only server-frozen inputs and
    # returns Pydantic-validated JSON. It has no tools or write credentials.
    suggestion = await suggestion_service.generate_validated(
        subject_ref=state["subject_ref"],
        evidence_refs=state["frozen_evidence_refs"],
    )
    return {"suggestion": suggestion.model_dump(mode="json")}


async def run_deterministic_gates(state: AdvancedWorkflowState) -> dict[str, object]:
    # Contract, provenance, sandbox, and promotion gates are code, not LLM judgment.
    status = await gate_service.evaluate(
        job_id=state["job_id"], suggestion=state["suggestion"]
    )
    return {"gate_status": "passed" if status.passed else "rejected"}


def route_after_gates(
    state: AdvancedWorkflowState,
) -> Literal["human_gate", "record_rejection"]:
    return "human_gate" if state["gate_status"] == "passed" else "record_rejection"


def human_gate(state: AdvancedWorkflowState) -> dict[str, object]:
    # This node contains no write side effect: interrupting/resuming re-executes it.
    decision = interrupt(
        {"job_id": state["job_id"], "suggestion": state["suggestion"]}
    )
    return {"human_decision": "approved" if decision == "approve" else "rejected"}


async def record_outcome(state: AdvancedWorkflowState) -> dict[str, object]:
    # A deterministic service writes append-only audit/event records after approval.
    await outcome_service.record_once(
        job_id=state["job_id"],
        gate_status=state["gate_status"],
        human_decision=state["human_decision"],
    )
    return {}


def build_workflow(checkpointer: AsyncSqliteSaver):
    graph = StateGraph(AdvancedWorkflowState)
    graph.add_node("authorize_and_freeze", authorize_and_freeze)
    graph.add_node("generate_suggestion", generate_suggestion)
    graph.add_node("run_deterministic_gates", run_deterministic_gates)
    graph.add_node("human_gate", human_gate)
    graph.add_node("record_rejection", record_outcome)
    graph.add_node("record_outcome", record_outcome)
    graph.add_edge(START, "authorize_and_freeze")
    graph.add_edge("authorize_and_freeze", "generate_suggestion")
    graph.add_edge("generate_suggestion", "run_deterministic_gates")
    graph.add_conditional_edges("run_deterministic_gates", route_after_gates)
    graph.add_edge("human_gate", "record_outcome")
    graph.add_edge("record_rejection", END)
    graph.add_edge("record_outcome", END)
    return graph.compile(checkpointer=checkpointer)


async def start_job(initial_state: AdvancedWorkflowState) -> dict[str, object]:
    async with AsyncSqliteSaver.from_conn_string(
        str(Path("data") / "operational-state.db")
    ) as checkpointer:
        workflow = build_workflow(checkpointer)
        config = {"configurable": {"thread_id": initial_state["job_id"]}}
        return await workflow.ainvoke(initial_state, config=config)


async def resume_approval(job_id: str, approved: bool) -> dict[str, object]:
    async with AsyncSqliteSaver.from_conn_string("data/operational-state.db") as checkpointer:
        workflow = build_workflow(checkpointer)
        config = {"configurable": {"thread_id": job_id}}
        return await workflow.ainvoke(
            Command(resume="approve" if approved else "reject"), config=config
        )
```

`authorization_service`, `suggestion_service`, `gate_service`, and `outcome_service` are application-owned dependencies to inject from the FastAPI domain layer. They are deliberately not LangGraph tools. The request handler must derive `job_id`, token identity, and permitted scope server-side; it must not accept them as trusted client authority.

### Key Abstractions
| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `StateGraph` | Typed, explicit graph of bounded state transitions. | Define authorization, suggestion, deterministic-gate, human-review, and record steps as inspectable nodes. |
| `AsyncSqliteSaver` | SQLite durable checkpointer with asynchronous persistence methods. | Compile every resumable Phase 4 workflow and preserve its per-job execution history in the existing operational SQLite boundary. |
| `thread_id` | Configurable checkpoint namespace and persistent execution cursor. | Set it to a server-generated job ID; reuse it only to resume that job, never to join user-controlled conversations. |
| `interrupt()` / `Command(resume=...)` | A durable pause plus an explicit resume payload. | Pause for the researcher approval required after deterministic promotion gates, then resume with a validated server-side decision. |
| Conditional edges | Deterministic routing function from state to named nodes. | Route a gate failure to an audited rejection and a pass to human review. Do not route on an unvalidated model claim. |

### Common Pitfalls
1. **Writing an external side effect before or inside `interrupt()`.** On resume, replay, or time travel, LangGraph re-executes the node containing the interrupt; a write, notification, or promotion there can run twice. Keep the pause node pure and put an idempotent, append-only `record_once` service in the following node.
2. **Treating `thread_id` as client-owned session state.** It selects persisted checkpoints. A guessed or reused value can expose or resume the wrong workflow. Generate it on the server, bind it to the authorization record, and verify ownership before reading, resuming, or streaming it.
3. **Using graph state as the system of record.** Checkpoints are replay/resumption state and may contain suggestions or intermediate data. Immutable viewpoint, experiment, promotion, token, and audit records belong in the existing SQLite operational-state repositories with explicit schema and idempotency keys.
4. **Allowing a model-selected tool call or conditional route to mutate state.** LangGraph permits arbitrary node logic; it does not grant policy enforcement. Treat model output as untrusted draft data, validate it with Pydantic and deterministic gates, and keep all actions behind application-owned services with server-derived scope.
5. **Calling synchronous graph/checkpointer APIs from FastAPI async paths.** SQLite I/O and model calls can block the event loop. Use `AsyncSqliteSaver` and `ainvoke`/`astream`; never call `asyncio.run()` inside a request handler or an already running event loop.

## 4. Implementation Guidance

**Model Configuration:** Use the existing OpenAI-compatible adapter; select deterministic settings for structured suggestions and preserve provider/model provenance.

**Core Pattern:** Graph nodes call deterministic authorization, audit, experiment, promotion, and sandbox services. Model output is validated structured data and cannot directly mutate authoritative state.

**Tool Use:** No unrestricted tools. Every action must be an application-owned, allowlisted operation with a server-derived scope.

**State Management:** Persist graph checkpoints per invocation using SQLite. Store operational records and append-only audit events in the existing operational-state boundary.

**Context Window Strategy:** Pass bounded subject references and server-frozen evidence; do not build context from mutable client inputs or raw unrestricted histories.

## 4b. AI Systems Best Practices

These controls apply to every Phase 4 graph. They supplement, rather than replace, the deterministic safeguards in authorization, sandbox, promotion, and audit services.

### 4b.1 Structured Outputs with Pydantic

```python
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, ValidationError


class ResearchSuggestion(BaseModel):
    """A non-authoritative model draft; it cannot contain executable code or authority."""

    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)

    kind: Literal["viewpoint_draft", "experiment_draft", "strategy_mutation_draft"]
    rationale: str = Field(min_length=1, max_length=2_000)
    evidence_refs: list[str] = Field(min_length=1, max_length=20)
    assumptions: list[str] = Field(default_factory=list, max_length=10)
    confidence: float = Field(ge=0.0, le=1.0)


async def request_validated_suggestion(adapter, prompt: str) -> ResearchSuggestion:
    """Adapter returns JSON text; capability-gate JSON Schema per provider."""
    last_error: ValidationError | None = None
    for attempt in range(1, 4):  # Initial attempt plus two bounded repair attempts.
        raw_json = await adapter.complete_json(
            system_prompt=SYSTEM_PROMPT,
            user_prompt=prompt,
            json_schema=ResearchSuggestion.model_json_schema(),
            max_tokens=900,
        )
        try:
            return ResearchSuggestion.model_validate_json(raw_json)
        except ValidationError as error:
            last_error = error
            await audit_service.log_model_schema_failure(
                attempt=attempt,
                error_types=[item["type"] for item in error.errors()],
                # Store a hash/length, not unbounded raw model or evidence content.
                response_sha256=sha256(raw_json.encode()).hexdigest(),
            )
            prompt = schema_repair_prompt(error.errors())
    raise SuggestionValidationError("Model returned no valid structured suggestion") from last_error
```

Use the existing adapter to pass an OpenAI-compatible JSON Schema `response_format` only when that provider/model advertises support; otherwise ask for JSON and enforce `ResearchSuggestion.model_validate_json()` locally. Pydantic validation is necessary but insufficient: resolve every `evidence_ref` against frozen server records, derive allowable scope server-side, reject unknown fields, and run deterministic contract/sandbox/promotion gates before a human review. After three invalid responses, mark the attempt as failed, persist redacted diagnostics and model/provider provenance, and surface a retryable controlled failure. Never auto-relax the schema or substitute a guessed value.

### 4b.2 Async-First Design
FastAPI routes, provider calls, and graph execution are async: use `AsyncSqliteSaver`, async node functions, `await workflow.ainvoke(...)` for a complete validated result, and `async for` over `workflow.astream(...)` only for controlled status/progress delivery. Keep the SQLite saver alive for the full invocation/resume scope; compile the graph against that saver in the dependency/lifespan boundary.

The common failure is calling `asyncio.run()` from an async FastAPI endpoint or an existing event loop. It raises at runtime and encourages blocking fallbacks. Await the coroutine instead. Use streaming for permitted UX progress events such as `authorized`, `gates-complete`, or `awaiting-review`; use `ainvoke` for model drafts because Pydantic validation, deterministic gates, and persistence must finish before any result is exposed as actionable. Do not stream raw tokens, tool arguments, or unvalidated suggestions to SSE clients.

### 4b.3 Prompt Engineering Discipline
Keep a versioned system prompt in the server-side `suggestion_service`: it defines the allowed draft schema, states that supplied evidence is reference material rather than instructions, forbids requests for authority/actions, and requires uncertainty to be explicit. The user prompt contains only the task, the server-derived subject reference, and a bounded set of frozen evidence excerpts. Client text, imported viewpoints, strategy descriptions, and tool-like text are untrusted data, never role instructions.

Use a small, versioned inline few-shot set only for stable output conventions such as an unevaluable viewpoint or an inconclusive experiment. Retrieve examples dynamically only from approved, versioned exemplars and label them as data; do not retrieve arbitrary historical content into the system prompt. Set `max_tokens` explicitly for every adapter request (initial budget: `900` output tokens for a suggestion); also set provider timeout, temperature, and request-size limits in the adapter. Production requests must never leave output tokens unbounded.

### 4b.4 Context Window Management
This hybrid workflow should not carry a raw conversational transcript through graph state. Each node receives identifiers plus a purpose-built, frozen context package. The evidence-preparation service ranks evidence by relevance and source grade, deduplicates, truncates each excerpt to a fixed character/token allowance, and records every included/excluded reference and truncation reason. Preserve identifiers and hashes in state; retrieve the authoritative frozen content at the node boundary.

When a package would exceed the configured model input budget, retain high-grade material evidence first, replace lower-priority material with deterministic extracts, and emit `insufficient_context` rather than silently dropping a decisive conflict. Summaries are non-authoritative derived artifacts: retain the source references, summary model/prompt version, and checksum; never overwrite original evidence. Checkpoints should retain compact IDs, status, and validated draft data rather than large raw prompts, market data, or model transcripts.

### 4b.5 Cost and Latency Budget
Set an explicit per-job budget before the model node runs: one primary structured-suggestion call plus at most two schema-repair calls, a provider timeout, and a maximum frozen-input/output token count. The adapter must calculate and persist actual provider/model token usage. Before provider pricing is selected, configure the limit with the provider-neutral formula `max_job_cost = 3 * (input_tokens * input_price + 900 * output_price)` and reject/defer a job when its remaining user/job budget cannot fund the worst case. Report observed p50/p95 latency separately for authorization, evidence preparation, model inference, gates, and checkpoint persistence.

Cache only immutable, non-sensitive work: exact-match cache keys should include the prompt version, model ID, decoding parameters, subject version, frozen-evidence hashes, and schema version. A semantic cache may assist low-stakes classification or evidence triage, but it must never reuse a draft across a different frozen evidence set or bypass gates/human approval. Route deterministic classification, scope checks, ranking, summarisation, and schema repair to code or the cheapest capable model; reserve the higher-capability model for the bounded research draft. Cache hits still create an audit event and still pass the same authorization and promotion controls.

## 5. Evaluation Strategy

本阶段以确定性服务的行为为主要评测对象。模型仅产生受限的研究草稿；任何授权、状态迁移、审计、沙箱准入、晋级或执行结论均须由代码验证。所有评测在本地 SQLite、固定市场数据快照和受控的假 Provider/Sandbox 上运行，**不得**连接券商、发送委托或运行未隔离的用户策略。

### Dimensions

| 有界 AI 草稿、安全与指令遵循 | **PASS:** 草稿严格符合 `ResearchSuggestion`：仅允许声明字段、1-20 个可解析的冻结 `evidence_refs`、0-1 置信度、限制长度；将证据/用户文本视为数据，明确不确定性，且不含可执行代码、权限请求、保证收益或交易指令。最多一次主调用与两次修复，预算耗尽或三次无效即受控失败。<br>**FAIL:** 未知字段、伪造/越权证据、提示注入指令、超长输出、行动性交易建议或无效 JSON 被放行，或为了成功而放宽 schema/重试上限。 | **Code:** Pydantic/引用解析/令牌与调用次数断言、注入和超长输出夹具。**LLM Judge:** 仅对“研究支持而非投资指令”、不确定性和证据贴合度评分；先与人工标注校准。 | High |
| 受控任务完成 | **PASS:** 对有效授权、完整冻结输入和可通过门禁的请求，任务到达已记录的草稿、拒绝、待人工复核或已批准结果之一，所有终态含可追踪审计 ID 和受控 SSE 状态；无无限循环或未结 checkpoint。<br>**FAIL:** 请求无终态、重复节点循环、SSE 暴露原始 token/未验证草稿，或以“完成”掩盖门禁拒绝与不可评估结果。 | **Code:** 端到端 fake-provider 场景、最大节点/恢复次数、终态与 SSE allowlist 断言。**Human:** 运营者抽查异常终态。 | High |

## 6. Guardrails

在线控制必须保持少量、确定性且快速；触发后阻断或进入显式人工处置，不尝试让模型自行修复安全问题。

### Online Guardrails
| Critical failure mode | 每请求实时控制 | 触发后的行为与证据 |
|---|---|---|
| 未授权、撤销、越界或超限任务开始 | 在创建 runnable job 前和 worker 实际开始前，服务器验证短期 token、主体绑定、任务类型、市场/证券 allowlist 交集、撤销与速率配额。 | 拒绝，不调用模型/沙箱、不发起 SSE 工作；写入不泄露 allowlist 细节的安全审计摘要。 |
| 跳过合法工作流或重放产生副作用 | Repository 在事务中验证合法前序状态、job ownership 与 idempotency key；`interrupt()` 节点无写副作用，结果写入使用 `record_once`。 | 返回受控冲突/拒绝；保留 checkpoint、请求关联 ID 与重复检测审计，绝不重复记录晋级或反馈。 |
| 模型/用户输入直接改变权威状态 | Pydantic `extra="forbid"`、字段/长度/调用预算检查，`evidence_refs` 对照服务器冻结集解析；图路由只读取确定性 gate 结果。 | 三次无效结构化响应或未知/越权引用即受控失败；保存哈希化诊断，不放宽 schema，不输出可行动草稿。 |
| 自定义策略逃离合同或资源限制 | 先执行合同、AST、import allowlist 校验；仅允许隔离进程，禁网络、限制文件权限，并施加 timeout/memory 限制。 | 拒绝或终止运行，记录约束原因和脱敏诊断；失败不能形成有效研究反馈或晋级证据。 |
| 无门禁或无人工批准的晋级/实盘动作 | 晋级 service 验证全部独立门禁证据、已绑定身份的批准时间与理由；依赖注入不提供 broker/execution capability，路由明确禁止 activation/order。 | 拒绝并审计缺失条件；即使通过晋级，仅注册研究策略版本，执行调用数必须为零。 |

### Offline Flywheel
| 节奏与样本 | 分析指标 | 改进闭环 |
|---|---|---|
| 每日，100% 拒绝、schema repair、超时/内存终止、状态冲突和 gate failure | 拒绝原因分布、重复率、schema 失败率、沙箱拒绝类型、无终态 checkpoint、门禁失败类别。 | 运营者将新颖原因归类为产品缺陷、恶意输入或预期拒绝；前两类在下一次变更前加入回归集。 |
| 每周，100% 晋级/修正/重试和 10% 成功草稿（至少 10 条） | 谱系完整率、证据可用时间、不可评估处理、OOS/成本门禁覆盖、批准理由完整率、置信度分桶及覆盖期。 | 量化研究员与数据治理负责人复核；发现的后见偏差、缺失标签或成本假设错误冻结相关晋级并回填金标。 |
| 每两周，全部 LLM Judge 与人工分歧及新增对抗输入 | Judge-人工相关性、对“研究支持非投资指令”的漏判、提示注入/伪造引用通过率。 | 未达到校准阈值则停用 Judge 作为决策信号，修改 rubric/样本后重新校准；对抗失败进入 Promptfoo 回归。 |
| 每月，24 个基线集全量重放 | 终态完成率、门禁回归、确定性重放差异、token/延迟和成本趋势。 | 仅在 Critical 用例零失败且无未解释谱系差异时升级提示、模型或工作流版本；所有差异保留比较报告。 |

## 7. Production Monitoring

### Tracing
在同一容器内启动 **Phoenix + OpenTelemetry**，以 `job_id`、`authorization_id`（哈希化）、`audit_event_id` 和 LangGraph `thread_id` 关联 trace。每个 span 记录 `authorize`、`freeze`、`model_draft`、`gate`、`human_interrupt/resume`、`sandbox`、`record_once` 的耗时和结果，以及 provider/model/prompt/schema 版本、token、重试数、门禁代码和证据哈希。不得导出令牌、原始市场数据、完整策略代码或原始模型输出；本地 trace 存储受容器卷和轮转/保留策略约束。

### Metrics And Alerts
| 指标 | 阈值与告警 | 处置 |
|---|---|---|
| 授权绕过、越权启动、缺二次校验 | 任意一次（阈值 `0`） | 立即禁用 advanced job 启动入口，保留审计/trace，人工复核受影响 job。 |
| 非法状态迁移、重复权威写入、无人工批准晋级、任何执行适配器调用 | 任意一次（阈值 `0`） | P0：冻结晋级和相关工作流，调查幂等键、checkpoint 重放和依赖注入边界。 |
| 审计/谱系字段缺失、冻结证据无法解析、未来数据时间戳 | 任意一次（阈值 `0`） | 阻止对应记录成为可晋级资产；启动数据治理复核与全量关联记录扫描。 |
| 沙箱逃逸信号或资源限制未生效 | 任意一次（阈值 `0`） | 停止自定义策略运行，保留脱敏取证并修复隔离配置后再启用。 |
| Pydantic/schema 失败、伪造引用、提示注入拦截 | 任意一次记录；5 分钟内 `>= 3` 次告警 | 保持阻断；检查提示/Provider 漂移和滥用来源，纳入每日 flywheel。 |
| 有效请求无终态或 checkpoint 反复恢复 | 15 分钟内 `> 1` 个，或 24 小时完成率 `< 99%` | 标记待恢复任务、暂停相同工作流版本并审查 checkpoint/SQLite 锁与节点重试。 |
| 模型延迟、token/调用预算 | `model_draft` p95 `> 30s` 连续 15 分钟，或任一 job 超调用/令牌/成本预算 | 降级为“稍后重试”的受控失败；不截断或放宽验证以追求完成率。 |

### Sampling And Review
- 100% 保留安全拒绝、状态/门禁事件、人工决定、沙箱事件及其脱敏 trace；成功模型草稿保留结构、版本、长度、哈希和 token 指标，原文仅按本地最小保留策略保存。
- 每周对成功草稿分层抽取 10%（每类至少 10 条），并对全部晋级、修正、不可评估及异常终态人工复核。抽样按高置信度、长输出、重试、反复恢复和用户重试加权。
- 每月比对离线 Judge/代码评分与人工复核、用户的重试/拒绝/撤销信号；当“自动评分良好”但人工否定、重试或撤销上升时，视为 signal-metric divergence，暂停相关提示/模型升级并扩充参考集。
