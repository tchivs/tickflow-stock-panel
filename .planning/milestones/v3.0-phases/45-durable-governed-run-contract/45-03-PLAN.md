<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| HTTP lifecycle request → server state machine | Client requests may ask for transition/retry/cancel but cannot choose resulting state or side effects. |
| JobStore/worker → run service | Adapter callbacks are untrusted and can be stale, duplicated, or malicious. |
| Process restart → SQLite recovery | Volatile worker state must not override durable facts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-45-06 | Tampering/Elevation | lifecycle transition service | high | mitigate | Explicit legal matrix, expected status/version SQL guard, atomic event+cursor writes, and terminal one-way checks. |
| T-45-07 | Tampering/Denial | retry/cancel idempotency | high | mitigate | Principal/request-key lookup, linked child semantics, cooperative cancellation boundary, and no late terminal overwrite. |
| T-45-08 | Tampering/Denial | worker restart callback and opaque attempt token | high | mitigate | Each running transition generates an opaque server token, only SHA-256 is persisted, callbacks require token plus expected transition_version, and cancel/terminal/retry/version changes invalidate old tokens. |
| T-45-12 | Information disclosure/Tampering | progress/retry/cancel service reads and writes | high | mitigate | Resolve the host principal, scope every repository predicate, expose bounded server-owned counters only, and use the same safe not-found boundary for cross-principal access with focused tests. |
</threat_model>
