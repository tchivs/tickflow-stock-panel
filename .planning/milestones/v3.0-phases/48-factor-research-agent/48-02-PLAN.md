<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Provider text → Stage 1 schema | Untrusted provider JSON crosses into a strict schema decode; unknown/missing fields are permanent failures. |
| Stage 1 proposal → factor catalog | A transient exploratory proposal must never become an admitted/catalog factor. |
| Partial result → caller | A degraded (some-failed-parse) result must not be presented as a clean complete one. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-48-02a | Tampering | provider text with an extra/missing field silently truncated or accepted | high | mitigate | `extra='forbid'` at every nesting level with field-specific rejection (hypotheses.py:87-93 pattern); unknown/missing → permanent `schema_violation`. |
| T-48-02b | Elevation / Spoofing | a raw provider expression trusted as canonical | high | mitigate | server `parse_factor` confirms every expression; only `canonical_expression` is persisted as authority; raw retained as provenance only (hypotheses.py:202-225). |
| T-48-02c | Elevation | a transient Stage 1 proposal leaking into the factor catalog / admission pool | high | mitigate | proposals live only in `research_alpha_proposals`; a registry lookup by `canonical_expression` returns None; promotion is Phase 49. |
| T-48-02d | Information disclosure | a partial result presented as complete | medium | mitigate | distinct `partial` flag on `Stage1Result` and every proposal row (R2); links to AF-REQ-25 Phase 50. |
</threat_model>
