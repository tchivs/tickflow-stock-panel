<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Preflight result → provider call | A `passed=True` preflight authorizes the first provider call; a failure MUST make zero calls. |
| Provider response → audit row | Untrusted provider text crosses into an immutable audit row; only a checksum is retained by default. |
| Provider failure → fallback | The most dangerous boundary: a provider failure MUST NOT produce a synthetic success. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-48-01a | Denial of service / Tampering | a failed preflight still issuing a provider call | high | mitigate | preflight is the only gate; `request()` is never reached when `PreflightResult.passed` is False; test asserts zero provider calls on failure (D-48-01). |
| T-48-01b | Tampering / Information disclosure | fabricated fallback draft on provider failure (SC4 violation) | high | mitigate | the seam's only success path is a real response; every exception class is table-tested to raise with a failed AnalysisRecord row and zero proposals (§5.4). |
| T-48-01c | Repudiation | a provider attempt with no durable evidence | high | mitigate | one append-only `research_alpha_analysis_attempts` row per attempt (success + every failure class), same DB as the checkpoint fence (OQ-1). |
| T-48-01d | Denial of service | unbounded retry storm on a transient error | medium | mitigate | `max_retries=3` with exponential backoff + jitter + cap 30s + cooperative cancel before each retry; SDK retry stays OFF. |
</threat_model>
