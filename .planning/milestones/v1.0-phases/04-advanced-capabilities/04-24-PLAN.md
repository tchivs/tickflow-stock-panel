## D-03/D-06/D-07 deployment-owned readiness descriptor

Before `run_phase1_fixture_sync` can construct `DataStore`, `backend/app/main.py` must parse and validate a `fixture_readiness` object in `ADVANCED_HOST_FIXTURE`, then pass that typed descriptor explicitly to the pre-write fixture preflight. The descriptor is the sole source of its benchmark symbol, non-empty configured symbols, required date-coverage range, exact evaluation windows `[20, 60, 120]`, installed strategy identifier with positive warmup trading-day count, aggregate-coverage range, and in-sample/out-of-sample ranges. Every endpoint is an ISO date; aggregate coverage contains required coverage and both split ranges; splits do not overlap; the strategy agrees with the persisted host research-asset binding. The preflight derives required trading-session coverage from this descriptor for each configured symbol and the benchmark. It invokes a pure bounded in-memory helper extracted from `bullish_alignment` that derives only MA/momentum prerequisites from raw bars and evaluates the production predicate before any DataStore/lake/view/cache write. No fixture-only predicate, browser semantics, or post-write enrichment is permitted. `test_market_data_fixture_contract.py` owns malformed descriptor/bar/no-signal matrix coverage; `test_production_host.py` owns valid and invalid lifecycle descriptor proofs.
