## Non-negotiable host-acceptance rules

1. Start only `uvicorn app.main:app` and let its real lifespan create the app state. Use a fresh temporary `DATA_DIR`, read-only Phase 1 fixture directory, and read-only schema-validated `ADVANCED_HOST_FIXTURE`; never inject a FastAPI dependency, replace a router, overwrite an `app.state` service, use an in-memory authority substitute, or call a service/repository/SQLite connection directly from Playwright.
2. Start the existing Vite dev server at `http://127.0.0.1:4173` only for static frontend/reverse-proxy delivery and pin its `/api`, `/health`, and `/api/intraday/stream` targets to the spawned Uvicorn process at `http://127.0.0.1:3018`. Login must occur through rendered same-origin `/api/auth/login`; assert the `tf_session` cookie has `Path=/` and is sent by browser-origin API and `EventSource('/api/intraday/stream')` calls. This transparent reverse proxy is explicitly permitted and is not Playwright route interception.
3. The deployment-owned fixture may supply static governed market inputs, approved built-in strategy identity, policy/scope settings, and a validated research-asset bootstrap declaration **only at host startup**. Validate every fixture field before use, reject missing/malformed/unknown fields before serving requests, and persist required fixture metadata through the normal lifecycle/repository path. It must not pre-create viewpoints, experiment specifications/runs/feedback, candidates, gate verdicts, promotions, jobs, sandbox validations, or sandbox runs.
4. Browser acceptance may use only visible UI interactions and ordinary same-origin HTTP against the Vite browser origin. It may use a real root `EventSource` observer to witness the same scoped stream that the application uses, but must not use `page.route`, `context.route`, `route.fulfill`, mocked `EventSource`, response fabrication, `page.evaluate` access to app services/local storage authority, fixture SQL, or direct service calls. The only test-side process management is spawn/readiness/teardown for the actual host.
5. Do not add browser endpoints for policy issuance, scope editing, revocation, sandbox proof, strategy registration, evidence creation, or gate outcomes. Keep fixture-selected revocation as a lifecycle-owned pre-execution hook and keep client payloads restricted to existing API schemas.
6. Do not make the Linux assertion assume `unshare`, user namespaces, mount permissions, or network namespace support. The spec must classify the actual host as `affirmative_isolation_proved` or `isolation_unavailable`; neither branch may be skipped, silently passed, or represented as unknown.
