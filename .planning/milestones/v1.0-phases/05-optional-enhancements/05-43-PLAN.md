## Scope threshold exception and file ownership notes

This plan intentionally retains its 12-file scope. Production code plus the corresponding regression and migration fixture are three indivisible transaction boundaries: (1) positive-parser policy → sandbox handoff → adversarial regression, (2) retry repository/service → forward migration → retry/migration fixtures, and (3) runner/optional-host lifecycle → marker registry → host/platform fixtures. Plan 05-44 already removes every acceptance-manifest, machine-report, parser and closeout concern from this implementation plan. Splitting again would expose shared retry/dispatcher/host contracts between plans while their migration and ownership invariants are still unverified.

Task ownership is otherwise disjoint. Task 1 exclusively owns `strategy_policy.py`, `sandbox.py` and `test_sandbox.py`. Task 2 exclusively owns `migrations.py`, `repository.py`, `service.py` and `test_operational_migrations.py`, plus only the retry/publication/recovery regions of `test_runner.py`. Task 3 exclusively owns `runner.py`, `optional_modules.py`, `pyproject.toml` and `test_phase5_optional_host.py`, plus only the dispatcher-close/cancellation/process-group regions of `test_runner.py`. The shared `test_runner.py` fixture is the sole intentional overlap, remains sequential inside this plan, and is required to prove that Task 2's dispatcher seam and Task 3's host ownership consume the same contract.
