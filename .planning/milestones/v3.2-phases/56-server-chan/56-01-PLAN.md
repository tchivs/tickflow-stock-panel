## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 用户→后端 settings API | SendKey 通过 HTTP 传入, 存储到 preferences JSON |
| 后端→sctapi.ftqq.com | 后端按用户 SendKey 向外部 API 发送 POST |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-56-01 | Information Disclosure | settings API 返回 SendKey | high | mitigate | GET /preferences 返回原始 sendkey 仅用于前端「已配置」判断; PUT 端点返回 secrets_store.mask 脱敏值 (per D-01)。考虑 GET 也返回 mask 而非明文 |
| T-56-02 | Tampering | SctChannel.deliver 错误信息 | medium | mitigate | _safe_error() 脱敏 sendkey, 不在 error/outcome 中泄露凭证; 审计 raw_hash 只存 hash 不存明文 |
| T-56-03 | Spoofing | sctapi.ftqq.com 端点 | low | accept | 固定 HTTPS 端点, sendkey 在 URL path 中 (Server酱官方设计), 与 Telegram bot token 在 URL 中同模式 |
| T-56-04 | Denial of Service | 每日推送上限 | medium | mitigate | SCT_DAILY_LIMIT=200, 超限降级为批量摘要 (per D-05), 防止刷屏与 API 限流 |
| T-56-05 | Repudiation | 推送审计缺失 | medium | mitigate | 每次 deliver 记录 ToolCallEnvelope(tool=sct, raw_hash + response_summary + duration), 审计页面可按 tool 筛选 (per D-04) |
</threat_model>
