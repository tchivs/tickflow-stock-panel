## Goal

把 38-01 的工厂接到两个生产构造点: app 引擎 (main.py) 与 research runner 引擎 (governed_runner.py `_service()`), 使生产路径的 `minute_loader` 从 `None` 变为工厂 loader。由于 kline_minute 湖当前 0 分区, 接线后的运行时行为必须与接线前逐字节一致 (required → 空 StrategyResult / optional → 跳过确认保留日线核心池) — 用「接线前基线 (38-01 T3) vs 接线后复跑」证明; 并用新增的结构门 + 空湖接线行为测试 + not_applied 锚点子集锁定。

### Wave-2 decisions (explicit)

1. **接线值**: main.py 用 `minute_loader=make_minute_loader(store.data_dir)` (`store` 已在该作用域, main.py:558 已用 `store.data_dir`); governed_runner.py `_service()` 用 `minute_loader=make_minute_loader(data_dir)` (`data_dir = Path(self._data_dir)` 已在 :59 定义, :60 已传 DataStore)。
2. **import 位置 = 本地 import**: 两处构造点都在函数体内 (main.py app 工厂函数 / governed_runner `_service()`), 照既有约定在构造点附近加 `from app.services.minute_loader import make_minute_loader` (main.py:551-552 已有 `from app.services.screener import ScreenerService` 同类形; governed_runner `_service()` 全部 import 都是本地)。governed_runner 的 import 必须留在 `_service()` 内 (spawn worker 内重建, 不进模块顶层 — 防 DuckDB 单例采集期导入, repo 约定)。
3. **行为保持证明方法**: 38-01 T3 五条命令的通过数为基线 → 接线后复跑同命令 → 通过数/测试名逐一相等; 另加一条生产形空湖测试 (T4) 直接断言 wired-required/optional 与 `minute_loader=None` 基线逐字段一致 (仅 `elapsed_ms` 除外)。
4. **结构门测试放 38-01 的测试文件**: `tests/test_minute_loader_wiring.py` 追加两个结构门用例 (main.py / governed_runner.py 含 `minute_loader=make_minute_loader(...)`), 镜像 test_auction_backfill.py:659-667 / test_auction_history.py:324-329 的 main.py 结构门形。接线回归由结构门 + 行为测试双锁。
5. **report 语义零改动**: 接线的是引擎构造 (策略执行面); 报告面 (auction_validation.py:434 硬编码 `"minute_confirm": "not_applied"`, auction_backtest.py:66 `_MINUTE_CONFIRM`) 不调分钟确认层 → 本 wave 只复跑 not_applied 锚点证明不破, 不新增报告面代码。
